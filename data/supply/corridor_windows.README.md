# corridor_windows.csv — Corridor windows (Data Spec §10.3)

The pre-planned corridor blocks: track-access windows already negotiated into the
working timetable, which the optimiser reads **directly** (Blueprint §5.1) instead
of detecting. These are the first of the two window sources the enumerator uses;
the other, traffic gaps, is derived at runtime from `train_paths.csv` and is not
stored here.

Generated by `data/generator/build_corridor_windows.py`; checked by
`data/checks/validate_supply.py`.

## Schema (Data Spec §10.3)

| Column | Type | Notes |
|---|---|---|
| `window_id` | string | `W-<from><to>-<line>-<DAY>`, e.g. `W-TRLAJJ-UP-SAT`. Primary key. |
| `block_section_id` | ref | The edge the window is on. |
| `day_of_week` | enum | `MON`…`SUN`. |
| `start_time` / `duration_min` | time / int | e.g. `01:00` / `120`. |
| `window_type` | enum | `corridor_block` here; `traffic_gap` / `requested` arise elsewhere. |
| `max_departments` | int | Practical ceiling on concurrent departments (≤ 3 — only ENG/TrD/S&T exist). |

**101 windows**: 28 trunk + 48 suburban + 20 freight + 5 branch.

## Generated from the documented pattern (Blueprint §5.4)

This is not real timetable data and does not pretend to be — Blueprint §5.4 states
the pattern is a modelled approximation, held in configuration, replaced wholesale
on deployment by the division's actual corridor block table. The rule set, verbatim:

| Corridor | Pattern | Here |
|---|---|---|
| `MAS-AJJ` quadruple trunk | 2 h per line per week, night 01:00–03:00, staggered across sections | `01:00`/120, 1×/wk, `max_departments` 3 |
| `MSB-TBM` saturated suburban | 3 h per line, twice weekly, 00:30–03:30 | `00:30`/180, 2×/wk, 3 |
| `AJJ-CGL` single line | 3 h once weekly, mid-morning (a daytime gap genuinely exists) | `10:00`/180, 1×/wk, 2 |
| `BBQ-GPD` freight | 2 h twice weekly, mid-morning, after the overnight peak | `10:00`/120, 2×/wk, 2 |

The freight and branch windows sit mid-morning for the same reason the goods
forecast troughs then — the overnight port peak has cleared. The suburban and
trunk windows sit deep in the night because that is the only time an EMU-saturated
line has capacity.

## Staggering — a corridor block must not sever its own section

The parallel lines of one span are deliberately placed on **different days**, so a
corridor block never takes every line of a multi-line span at once (FR-21, "never
sever a section" — Blueprint §2.2). Days are assigned from the edge's position in
its corridor; the second weekly occurrence lands three days on. `TRL-AJJ`'s four
lines, for example, fall on THU/FRI/SAT/SUN — one line down at a time, three always
open. `validate_supply.py` fails the build if any multi-line span is ever fully
blocked on one day.
