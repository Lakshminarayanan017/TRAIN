# block_executions.csv — Block execution history (Data Spec §11.1)

The training set (bucket 4). One row per block worked over the past year, carrying
what was **requested**, what was **sanctioned**, and what **actually happened** —
the target for the duration model (`actual_end − actual_start`) and the availment
model (`availed`) at once.

Generated by `data/generator/build_block_executions.py`; checked by
`data/checks/validate_history.py`.

## Schema (Data Spec §11.1)

`block_id`, `block_section_id`, `tasks_included` (`;`-list), `departments`,
`merge_group_id`, `requested_start`/`requested_duration_min`,
`sanctioned_start`/`sanctioned_duration_min`, `actual_start`/`actual_end`,
`availed`, `overrun_min`, `overrun_reason`, `crew_id`, `machine_id`, `weather`,
`season`, `was_merged`. **2,343 rows.**

## Synthetic — but no live source could exist

Spec §11 calls this "the bucket nobody currently has": no system records
actual-vs-requested duration, which is *why* the field app is being built. So it
is synthesised. What makes it useful is that every relationship the models must
learn is deliberately present (a model trained on inert features learns nothing):

| Relationship | How it shows up | Verified by the validator |
|---|---|---|
| **Positive overrun bias** (§12.3) | actual/requested ≈ **1.08** singleton | printed each run |
| **Merged is slower per task** (Blueprint §8.1) | actual/requested ≈ **1.23** merged | `was_merged` guard |
| **P80-consistent overrun** (Blueprint §7.5) | ~**24%** exceed the *sanctioned* buffer | printed each run |
| Weather / machine-late lengthen the job | monsoon & `machine_late` lift duration | — |

## Grounded where the world is real

- **Built from the actual `done` tasks** in `tasks.csv`, so `tasks_included`,
  `departments`, `crew_id` and `machine_id` are **real references**, and every
  task lands in **exactly one** block (the validator fails on any double-count).
- **Weather / season** follow Chennai's real Oct–Dec north-east monsoon (576 of
  2,343 blocks are in monsoon; heavy rain is concentrated there).
- **Historical merge rate ~13%** — the incidental rate of Blueprint §12.2, because
  departments do *not* coordinate today. Raising it is the system's whole point.

Not-availed blocks carry empty `actual_start`/`actual_end` (the block was
sanctioned but never worked) — `availed` and the presence of actuals are kept in
lockstep by the validator. Node-only disconnection blocks are placed on the
station's busiest incident edge, since §11.1 requires a `block_section_id`.
